Architectural Comparison: Persistent Cluster vs Serverless FaaS

Dimension Persistent Multi-Worker Pool Serverless FaaS Runtime
Startup Latency Zero startup delay (~0.5ms inference) Cold start penalty (~220ms init), warm reuse (~0.5ms)
Resource Provisioning Static pre-warmed dedicated worker pool On-demand ephemeral container; teardown on idle timeout
Memory & Idle Cost Continuous memory allocation even when idle Zero cost and zero active memory when idle
Scaling Model Fixed capacity; queue/failover across provisioned nodes Elastic horizontal auto-scaling per request invocation
Ideal Workload Steady, high-throughput, latency-critical inference pipelines Burst-heavy, sporadic, or cost-sensitive intermittent calls
